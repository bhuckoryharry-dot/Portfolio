Java

MediClinic Management System

A Java Swing desktop application for managing a small medical clinic’s day-to-day operations: registering patients and doctors, scheduling consultations and searching records. All data is held in memory using custom-built singly linked lists, with no external database.

Java Swing Linked Lists OOP CRUD

Purpose

A coursework assignment (Assignment 2) built to demonstrate GUI programming, object-oriented design and manual implementation of linked list data structures.

Core functionality

  • Patient registration: NIC, name, date of birth, address and contact number, shown in a table with update and delete through modal dialogs.
  • Doctor registration: auto-generated doctor IDs with similar CRUD functionality.
  • Consultations: pick a patient and a doctor from combo boxes, enter a date (defaults to today) and remarks.
  • Search: patients by NIC or partial name, doctors by ID or partial name, and consultations by ID.

Custom data structures

  • PatientLinkedList, DoctorLinkedList and ConsultationLinkedList, hand-written with add, find, delete and update operations (no java.util.LinkedList).
  • Patient, Doctor and Consultation node classes, each carrying a next reference.

Validation & integrity

  • Required-field checks on registration and update forms.
  • Duplicate NIC prevention for patients.
  • Deletion blocked when a patient or doctor is linked to an existing consultation.

Technologies

  • Swing components: JFrame, JTabbedPane, JTable, JComboBox, JTextArea, JOptionPane, JDialog.
  • Layouts: BorderLayout, GridBagLayout, FlowLayout.
  • DefaultTableModel with read-only cells; lambda-based ActionListeners.
  • java.time.LocalDate with DateTimeFormatter (dd-MM-yyyy).
  • System look and feel, and SwingUtilities.invokeLater for thread-safe startup.
  • Pre-loaded sample data so the app is demonstrable on launch.

What I learned

  • Building a multi-tab desktop GUI from scratch.
  • Implementing and manipulating linked lists manually.
  • Separating the UI from the data layer.
  • Enforcing data integrity rules without a database.
SQL

Applicant Management System

A database-driven application for the University of Technology, Mauritius, designed to replace manual, error-prone handling of student applications. I designed the relational database and built Oracle Forms screens on top of it.

Oracle SQL PL/SQL Oracle Forms ER Modelling 22 tables

Overview

The system stores applicants’ personal details, programme choices, SC and HSC exam results, other qualifications, employment history and medical history. The design is normalised and uses junction tables to model many-to-many relationships. Users can create, view, update and delete records through the forms, while primary and foreign keys keep the data consistent.

Project evolution (3 stages)

  • First deliverable: a student registration system covering programme enrolment, qualifications, employment history, guardians and emergency contacts, with business rules, an ER model and sample data.
  • Second deliverable: a redesign around applicants, adding SC and HSC exams with subjects and grades, schools, positions, employers and medical history, plus new business rules and logical and physical models.
  • Final build: a working Oracle implementation with SQL scripts and five Oracle Forms screens.

Database design

  • 22 tables: 13 entity tables (e.g. APPLICANT, MEDICAL_HISTORY, EMPLOYER, SCHOOL, GRADE, SC_EXAM, HSC_EXAM) and 9 junction tables (e.g. APPLICANT_STATUS, APPLICANT_SC_EXAM, HSC_EXAM_SUBJECT).
  • Composite primary keys on junction tables, foreign keys throughout and NOT NULL constraints.
  • CHECK constraints restricting subject grades to A–E.
  • Reserved-word conflicts resolved by renaming tables (POSITION_TBL, STATUS_TBL).
  • Documented business rules, logical model and physical model.

SQL & Oracle features

  • A re-runnable PL/SQL script that drops existing tables inside an anonymous block with exception handling, recreates the schema and loads sample data.
  • TO_DATE for all date inserts.
  • Sequences (APP_ID_SEQ, MED_ID_SEQ, QUA_ID_SEQ, SC_EX_SEQ) for auto-generated IDs.
  • A view (AQ_BLOCK) joining applicants to qualifications.

Oracle Forms application (5 forms)

  • Applicant medical, applicant SC exam, applicant HSC exam, SC exam and HSC exam forms.
  • Master-detail data blocks (exam → subjects → grades) linked by key columns.
  • NEW, SAVE, UPDATE, DELETE and LIST buttons handled by WHEN-BUTTON-PRESSED triggers.
  • Embedded INSERT, UPDATE and DELETE statements with COMMIT, and NEXTVAL calls to generate IDs.
  • Radio-button groups for grade entry and a university logo for branding.

Tools

Oracle Database, Oracle SQL and PL/SQL, Oracle Forms Builder, ER and logical/physical modelling, Microsoft Word for documentation.

Website

Movie Store: ASP.NET Web Forms

A multi-page movie store website built with C# and ASP.NET Web Forms on .NET Framework 4.8. Visitors browse a catalogue, read the About, Gallery and Testimonials pages, send a message through a contact form, sign up, log in, choose a movie and complete a simulated checkout.

C# ASP.NET Web Forms .NET 4.8 Bootstrap 5 Session State

Pages & features

  • Home: movie catalogue (title, genre, price, image) displayed with an asp:Repeater and a Buy button on each card.
  • Login: required-field validators, a “Remember me” cookie that lasts 30 days, and a returnUrl redirect with a local-URL check so the app only redirects to its own pages.
  • Sign Up: form validation, then the user is registered and logged in automatically.
  • Payment: redirects to login if you’re not signed in, shows the selected movie and price, validates the form fields and shows a success panel (simulated checkout).
  • About, Gallery, Testimonials, Contact: content pages, with a validated contact form.
  • Layout: three master pages (guest layout, store layout and the default site master with a mobile variant) showing login status and a logout button.

Technologies

  • C#, ASP.NET Web Forms (.aspx with code-behind), .NET Framework 4.8.
  • Bootstrap 5, custom CSS (movie theme, layout and menu styles), responsive grid and a media query for small screens.
  • jQuery, Modernizr, Newtonsoft.Json, ASP.NET Web Optimization (bundling and minification), FriendlyUrls, MS Ajax ScriptManager.
  • Visual Studio 2022 and IIS Express.

Concepts demonstrated

  • Master pages and content placeholders.
  • Page lifecycle and postback handling (IsPostBack).
  • Event-driven programming (ItemCommand and Click handlers).
  • Session state (selected movie, logged-in user) and application state with Application.Lock().
  • Cookies, form validation, and route and bundle configuration in Global.asax.
  • Object modelling with a Movie class and LINQ-style List.Find.
Learning project: this site has no database. The catalogue is a hard-coded list, accounts live in application memory and the payment is a simulated checkout only. It was built to practise ASP.NET Web Forms concepts, not for production use.

Planned upgrades

  • Move the catalogue and users into SQL Server or SQLite.
  • Hash passwords (e.g. BCrypt) and remove the password cookie.
  • Add an orders table and a shopping cart.
